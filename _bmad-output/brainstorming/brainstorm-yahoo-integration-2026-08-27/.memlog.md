## Synthesis — Chosen Approach

**Goal:** Bring Chino's two Yahoo leagues into Volatile as ongoing, auto-refreshed data so they appear alongside Sleeper/Fleaflicker/MyFFPC in the existing dashboard, team pages, free-agent views, and Suggested Transactions. Read-only + recommendations for now; write-back deferred.

**The plan (Idea 1 + Idea 4, sequenced):**
1. Register one Yahoo developer app (Chino's own). One-time OAuth2 flow via a local script → capture a long-lived REFRESH TOKEN → store in env/Supabase. No login UI, no per-user auth.
2. Build a `getYahooLeagueData(leagueId)` adapter: refresh access token → call Yahoo Fantasy API → normalize into the SAME shape existing connectors return (teams, each team's roster, free agents, scoring settings).
3. Write normalized data into the SAME leagues / rosters / roster_players tables MyFFPC uses, tagged platform:'yahoo'. Every existing feature then works for free.
4. Schedule a cron (mirror the FantasyCalc/market-values pattern) to refresh both leagues automatically. No manual upkeep.

**Watch during build (not blockers):** Yahoo player-name → players DB matching; Yahoo scoring-settings → app format mapping (1QB/SF, PPR); refresh-token longevity across the season.

**Explicitly out of scope:** public multi-user "log in with Yahoo", write-back to Yahoo, scaling.

**Template payoff:** this scheduled-pull→normalize→upsert pipeline generalizes — later it can automate MyFFPC (swap paste for a fetch adapter) and slot in write-back via a Playwright robot if desired.
