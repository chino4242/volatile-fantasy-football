# UX Memlog — Live Draft On-the-Clock Experience

topic: Reduce overwhelm in the live draft tool when on the clock; ground recommendations against the user's current roster.

---

- [event] Create mode started. Focused UX improvement on the live draft on-the-clock experience (reusing DraftClient, mode="live").
- [decision] Confirmed pain point: the on-the-clock moment presents too many competing decision surfaces at once (blend slider, primary rec card, 5-row rec table, full available-players table, tabbed board/scarcity/roster/needs panel, trade tools) with no clear visual hierarchy for where to look first.
- [decision] User likes the recommendations. Core desired improvement: show a view of "my team so far" right next to the recommendations, to ground each pick decision against current roster state.


- [decision] The roster panel is a "results / validation" surface, NOT a need-calculator or prescriptive engine. Its job: let the user validate the recommendation against reality and pick with confidence. User keeps agency as the judge.
- [decision] Recommendations stay exactly as-is (same scoring engine, same ranked list). No roster-reactive changes to the rec logic. The roster panel provides context only.
- [decision] "My team" panel content: all three — (a) counts by position, (b) players listed grouped by position with tier/quality indicator, (c) total value per position. Shown at a glance.
- [decision] The on-the-clock mental model / confidence loop: glance at my team (results) → read the recommendation → judge "does this fit?" → pick with confidence. Panel and rec sit side-by-side.
- [assumption] This is a layout/composition change to the on-the-clock view, not new data — roster composition, position counts, and per-position value already exist in the app (Roster tab, position value cards). We are surfacing/repositioning them next to the recommendation rather than inventing new computation.


- [decision] On-the-clock HERO = recommendation + "my team" roster panel as a paired unit at the top. Everything else demoted below / collapsed.
- [decision] Full available-players table is a co-star (actively used for validation/override), not noise. Keep it accessible on the clock, below the hero. DEFAULT SORT = Auction value (redraft_auction_value), descending. (Note: today's default sort is dynasty/effective value — this is a change.)
- [decision] Suggest Trade / trade tools during the draft are barely used — minimize or remove from the on-the-clock view. Move behind a button/collapsed, deprioritized.
- [decision] Primary surfaces: BOTH mobile and desktop. Desktop = true side-by-side rec+roster; mobile needs a stacked/compact treatment of the same pairing (responsive concern is in scope).


- [event] Rendered on-the-clock wireframe (desktop side-by-side + mobile stacked) to .working/flow-on-the-clock-2026-08-27.excalidraw. Desktop: sticky YOUR PICK bar; hero row = Recommendations (left, ~60%) + My Team results panel (right, ~40%); Available Players (auction$ default sort) below; Board/Scarcity/Needs + Trade collapsed. Mobile: YOUR PICK bar → compact team strip (QB1 RB3 WR2 TE0, tap to expand) → recommendations stacked → available players.


- [decision] LAYOUT APPROVED. Desktop: rec-left / team-right hero split. Empty-position ⚠ flag KEPT (light validation cue, acceptable — not prescriptive). Mobile: compact one-line team strip (counts + ⚠) above recs, tap-to-expand for full breakdown.
- [decision] Available Players table MUST sort by Auction $ descending by default (highest $ at top). Mockup corrected to show true descending order (McLaurin $21 > Tuten $19 > Odunze $17 > Hubbard $6 / Purdy $6). This is the canonical default sort behavior for the on-the-clock table.
- [event] HTML mockup rendered + approved: .working/on-the-clock-mockup.html (desktop/mobile toggle).


- [decision] The #1 recommendation must prominently show its "why" (rationale) in the paired hero. This functionality ALREADY EXISTS in DraftClient and must be preserved/surfaced, not rebuilt. Components of the "why":
    (a) "Fills:" line — roster slot addressed, e.g. "RB3 (starter) — you have 2 RBs"; starter vs depth.
    (b) "Edge:" sentence — dynamically built from scarcity (# comparable players left), competition (# teams ahead needing the position), and roster need. Plain-English rationale.
    (c) Tags — Elite Prospect, ZAP ↑, Dynasty Buy, Redraft ↑, Need, etc.
    (d) 💡 Strategic wait/grab callout — survival-probability logic: "#1 projects X% available at your next pick; consider grabbing Y now — only Z% likely to last, N value at risk. You may land both." Shown only when #1 is safe to wait AND another candidate is at real risk.
- [assumption] No new reasoning computation needed — the on-the-clock redesign surfaces the existing rationale (Fills/Edge/tags/strategic callout) as a first-class part of the rec hero, kept adjacent to the My Team results panel.


- [decision] My Team panel: per-position (count · Σ value · players w/ tier · ⚠ empty flag) PLUS a small top-line "starters filled" summary (e.g. "8/10 starters set") to reinforce the confidence read. Approved.
- [decision] Reviewer Gate: skip heavy validation for this focused single-view change. Proceed straight to finalizing spines. (Accessibility still addressed inline via the Accessibility Floor section — color cues paired with text/labels, contrast, mobile tap targets.)
- [event] Scope locked. Finalizing DESIGN.md + EXPERIENCE.md for the live draft on-the-clock experience.

Reason: the recommendation render is a ~1600-line deeply-nested inline IIFE; a grid restructure carried high regression risk to the shared mock draft. The compact strip still delivers the core requirement (roster grounded adjacent to the rec, glanceable, tap-to-expand full breakdown). Revisit for true side-by-side later if desired.
